# antislop Audit — SquidWeave

**Date:** 2026-10-10  
**Scope:** `knol3j/squidweave` landing page (`ui/src/sections/*`), app UI (`ui/src/pages/*`, `ui/src/components/*`), and recently touched backend files (`src/lib/tier.mjs`, `api/ad-routes.mjs`, `src/env.mjs`).  
**Skills used:** antislop (core), antislop-ui, antislop-human, antislop-copywriting, antislop-code.  

---

## Executive Summary

The landing page is a recognizable AI-default SaaS template: dark hero with indigo/violet gradient, particle canvas, animated grid, fade-up cards, 3 pricing tiers, and fabricated statistics. The app UI (`Advertising`, `MissionControl`, etc.) is built on extensive mock data that is rendered as if real. Hard Gate violations are numerous, especially fabricated numbers/data (R-17/R-38), contrast failures (R-25), dead navigation (R-24/R-26), and em dashes (R-02). No `DESIGN.md` or equivalent brand direction was found, so the design should be labeled *draft without direction* with honest default dials **ENERGY 1 / RHYTHM 1 / MOTION 1** until a real brief is supplied.

## Delivery Gate Status

Running the core Delivery Gate against the current codebase yields the following honest result:

**Block 1: Hard Gate — FAIL**
- R-02: em dash in `Hero.tsx` and `Traction.tsx`.
- R-17 / R-38: fabricated statistics in `Hero`, `Problem`, `Traction`, `Pricing`, `useStore.ts`, `Advertising.tsx`, and `api/ad-routes.mjs`.
- R-24 / R-26: dead sidebar links in `Sidebar.tsx` and dead "Documentation" link in `Footer.tsx`.
- R-25: contrast failures on dark cards (`text-slate-500` / `#0a0e1a`), light sections (`text-slate-400` / `#f8fafc`), and app UI (`text-[#64748B]` / `#111827`).
- R-27: empty/loading/error states are not consistently implemented across data views.
- R-36 / R-38: unqualified "99.9% uptime SLA" and "safe and compliant" claims.
- R-37: no `DESIGN.md`; design must be labeled *draft without direction* with dials ENERGY 1 / RHYTHM 1 / MOTION 1.

**Block 2: Purpose-Gate — FAIL**
- R-01: indigo/violet gradient is the default palette.
- R-07: animated grid background.
- R-09: repetitive eyebrow badges.
- R-13 / R-19: endless glow/pulse animations.
- R-14: identical feature/problem cards.
- R-05: default landing-page structure and 3-tier pricing.

**Block 3: Liveliness — FAIL**
- Dials are not declared (no direction).
- No single focal point per screen; everything competes with glow/gradient/motion.
- Identity motif is missing.

**Block 4: Craftsmanship & Quality Locks — FAIL**
- C-3: roadmap section is speculative filler.
- C-5: fabricated numbers and claims.
- R-15 / R-16: generic CTAs and buzzwords remain.
- R-31: no written rationale for design decisions.

**Overall: FAIL.** The landing page and app UI do not pass the antislop Delivery Gate.

## Recommended Fix Order

1. **Remove or label fabricated data** (H-01–H-07): replace hardcoded stats with real numbers or `[REAL DATA]` placeholders, and empty mock store arrays until real data flows in.
2. **Fix contrast** (H-08–H-12): darken helper text on light backgrounds and lighten helper text on dark backgrounds until every pairing passes 4.5:1.
3. **Fix dead navigation** (H-13–H-14): remove sidebar links to unbuilt pages, or add "Coming soon" labels and `// TODO` comments.
4. **Remove em dashes** (H-15–H-16): replace with commas or periods.
5. **Add honest empty/loading/error states** (H-17) before relying on real data.
6. **Resolve design direction** (L-02): create `DESIGN.md` or label the output *draft without direction*.
7. **Reduce default patterns** (M-01–M-18): cut gradient overuse, grid background, generic badges, and template layout.
